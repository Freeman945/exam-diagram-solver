## 5. 失败与缺陷详情

### 5.1 几何图标签压住顶点（C2 / C6 / C8）

- 输入样例：C2、C6、C8
- 预期：标签在点外侧，不压住点、不压住线段
- 实际：A 标签落在顶点右下方并压住顶点；D 标签压住 D 点
- 首个出错模块：**DIAGRAM_RENDERING**
- 原因定位：`DiagramSpec.label_offsets` 的语义不一致。提示词与 Schema 示例按屏幕像素理解（`"A":[10,-8]`，负 y 向上），而 Renderer 把它当世界坐标方向并做 y 翻转，导致模型给出 `"A":[0,-14]` 时标签被放到下方。
- 下游影响：不影响几何关系的数值校验，图形仍可用；但降低图形可读性与“作答图”的规范性。
- 修复方向：统一 `label_offsets` 语义（建议明确为屏幕像素偏移，并在渲染器中直接使用）；或在标签落点落入多边形/距点过近时拒绝该 hint，回退到自动避让。

### 5.2 函数图标题重复（C4 隔离测试）

- 输入样例：C4（隔离 `exam_create_diagram_spec`）
- 预期：标题出现一次；曲线标注只标 `y=x²−2x−3`
- 实际：左上角标题与右上角曲线标签内容相同，重复
- 首个出错模块：**DIAGRAM_RENDERING**
- 原因定位：`render_coordinate` 在 `mark_key_points` 分支中把 `spec.title` 同时作为曲线 label（`curves_spec.insert(... label=spec.get("title"))`），与画布标题重复。
- 修复方向：曲线缺省标签不要取 title；或仅在未设置 title 时使用。

### 5.3 `exam_grade_answer` 的图参数失效

- 输入样例：C3（`diagramRendered=true, diagramRole=both`）与 C7b
- 预期：已渲染图时不应再扣“没有图”
- 实际：仍扣 2 分并给出“题目要求作图，但答案中没有图”
- 首个出错模块：**EXAMINER**（工具参数到 pipeline 的传递）
- 原因定位：`tools.js` 把 `{rendered, role}` 传给 `pipeline.gradeSolution`，但 `gradeSolution` 只用 `Boolean(diagram?.files)` 判断是否渲染，忽略了 `rendered` 字段；阶段工具没有 `files`，因此始终为 false。
- 下游影响：端到端内部评分正常（有 files），但单独调用评分工具时结果错误，会误导 Agent 触发无意义的修订。
- 修复方向：`gradeSolution` 优先使用 `diagram.rendered`，缺失时再回退到 `Boolean(diagram.files)`。

### 5.4 输出预算截断导致整段失败（C4 / C7a）

- 输入样例：C4（作图规划）、C7a（解题）
- 预期：结构化输出或解答完整；预算不足时重试或降级
- 实际：模型在 7000/9000 token 处截断，C4 无图、C7a 直接抛错 `LLM_TRUNCATED`
- 首个出错模块：C4 **DIAGRAM_SPEC**；C7a **SOLVER**
- 原因定位：内部调用继承 `reasoningEffort: max`，推理占用全部输出预算；`planDiagram` 的修复循环只处理校验失败，不处理 LLM 调用失败，首次截断即中止整个作图阶段。
- 下游影响：C4 的 Solver/Examiner/Final 都受前序缺图影响；C7a 没有产生任何答案。
- 修复方向：对结构化调用限制/降低 reasoning effort 或显著提高 maxTokens；对 `LLM_TRUNCATED` 做一次“提高预算 + 缩短提示”的重试；失败时降级为“无图文本答案”而不是中止。

### 5.5 信息不足时缺少统一门禁（C7 / C9）

- 输入样例：C7（缺 μ，置信度 0.52）、C9（空白，置信度 0）
- 预期：识别信息不足时停止解题，返回 `NEED_MORE_INFO`，明确请求用户补充图片
- 实际：C7 继续作图与求解；C9 继续走完流程，拒绝文本被当作正常答案，status=ok、10/10
- 首个出错模块：**PROBLEM_PARSING**（缺少“信息充分性”判定与门禁）
- 下游影响：C7 触发 Solver 截断；C9 触发 Examiner 误判满分，Final Rendering 输出误导性的“自检通过”。
- 修复方向：在识别后增加门禁（`recognition_confidence` 阈值、`raw_text`/`questions` 为空、关键条件缺失）；不通过时返回结构化的“需要补充图片”，并让 status 不为 ok、Examiner 不打分。

### 5.6 Validator 误报“无单位”（C7b）

- 输入样例：C7b（参数化解，含条件分支 `a=0`）
- 预期：最终答案 `a=(5−10μ) m/s²` 有单位；条件分支中的 `a=0` 不应被当作最终答案
- 实际：`physics:unit:a` 失败，细节为“a has no unit”
- 首个出错模块：**VALIDATOR**
- 原因定位：`_answer_unit_checks` 用正则扫描整个 `final_answer` 中所有 `symbol = number` 形式；`a=0` 被当作一次量的声明，且没有上下文（条件分支、中间结果）过滤。
- 下游影响：Examiner 据此扣 3.5 分，正确答案被评为 8.5/12，并触发修订指令。
- 修复方向：只解析结论句（如“故/答/所以”之后）或最后一个赋值；同一符号多次赋值时取最终值；对无单位但显式无量纲的表达式豁免。

### 5.7 无关断言可通过 Validator（C9）

- 输入样例：C9
- 预期：空白题不应产生“程序校验通过”
- 实际：AnswerSpec 中的两条 `numeric` 断言（数值 `2.727272727`）与题目无关，Validator 仍判定通过
- 首个出错模块：**VALIDATOR**（断言相关性）
- 下游影响：Examiner 认为“程序验证通过”，给出满分。
- 修复方向：要求断言至少引用题目中的符号/方程/数值；对“题目为空”直接拒绝执行验证；报告 coverage 时区分“相关断言”和“无关断言”。

### 5.8 Examiner 对拒绝作答给满分（C9）

- 输入样例：C9
- 预期：无题目、无答案时不给分，或标记 `not_applicable`
- 实际：10/10，`revision_required=false`
- 首个出错模块：**EXAMINER**
- 原因定位：规则评分只检查“最终答案非空、步骤数、关键步骤、作图”，没有“答案是否回答了题目”的判定。
- 修复方向：增加 `answer_kind`（solution/refusal/insufficient_info）；拒绝类回答不计分并报告原因。

## 10. 最严重的 5 个问题

1. **结构化调用被推理预算截断**（C4、C7a）
   `reasoningEffort=max` 下，7000/9000 token 的输出预算被推理占满，作图规划与解题会直接失败；作图阶段首次失败即中止，重试机制不覆盖 LLM 失败。影响核心用例（函数作图题、信息略复杂的物理题）。

2. **信息不足时没有门禁**（C7、C9）
   识别已经给出 0.52/0.00 的置信度和明确的不确定性描述，流水线仍继续作图与求解；C9 甚至以 `status: ok`、10/10 结束。这不是“表达不确定性”，而是“带着不确定性继续给出正式答案”。

3. **Validator 对条件分支/多次赋值误报**（C7b）
   正确答案因 `a=0`（静止分支）被判“无单位”，Examiner 扣 3.5 分并触发修订。误报比漏报更伤：它让正确答案看起来是错的，并浪费一轮修正。

4. **Examiner 无法识别“拒绝作答”**（C9）
   空白题得到 10/10 与“程序验证通过”，评分体系在最需要保守的场景给出了最自信的结果。

5. **`label_offsets` 语义不一致导致标签压点**（C2、C6、C8）
   三张几何图的 A/D 标签都压住顶点。图形关系是正确的，但作为“作答图”不够规范；根因是提示词/Schema 与 Renderer 对偏移量的解释相反。

附带问题：函数图标题重复；`exam_grade_answer` 的 `diagramRendered` 参数失效；C8 的 `attributes` 数组触发一次结构修复（提示信息偏内部）。

## 11. 建议修复顺序

| 优先级 | 问题 | 建议 |
|---|---|---|
| P0 | 输出预算截断 | 结构化调用不继承 `max` reasoning，或按任务设置更合理的 maxTokens；对 `LLM_TRUNCATED` 做一次提高预算的重试；作图失败时降级为“无图答案”而不是中止 |
| P0 | 信息充分性门禁 | 置信度阈值 + 空题干/空问题/关键条件缺失检测；不满足时返回 `NEED_MORE_INFO` 与明确补图提示；status 不得为 ok |
| P1 | Validator 上下文 | 只解析结论句或最后一次赋值；同一符号多次赋值取最终值；符号量无单位时区分“条件分支中间量”与“最终结论” |
| P1 | Examiner 拒绝识别与图参数 | 增加 `answer_kind`；拒绝类不给分；修复 `gradeSolution` 对 `diagram.rendered` 的读取 |
| P2 | 图形标签 | 统一 `label_offsets` 为屏幕像素；标签落入图形内部或距点过近时回退自动避让 |
| P2 | 函数图标题重复 | 曲线标签不再复用 `title` |
| P3 | DiagramSpec 语义 | 题目给定的线段不要放入 `auxiliary_segments`（C2 隔离用例中 AD 被画成红色虚线） |
| P3 | 结构修复提示 | `attributes` 允许标量以外的值，或把修复提示改为用户可读的“识别结果已自动整理” |

## 13. 结论

- 核心链路（识别 → 判断 → 作图 → 解题 → 校验 → 评分 → 输出）在**信息充分、模型不截断**时可用；C1、C2、C3、C5、C6、C8 六个用例给出了正确且可誊写的答案。
- 当前版本**不能通过完整验收**：函数作图题会因截断丢图；信息不足时缺少门禁；Validator 有一次误报；Examiner 会给拒绝作答打满分。
- 上述问题均已定位到具体模块与代码位置，修复顺序见第 11 节。修复后建议用同一套 9 个用例回归，并补测第 12 节列出的 NOT TESTED 项。
